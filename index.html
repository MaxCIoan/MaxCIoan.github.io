Proof Notes

The story behind the work.

This is the part I want reviewers to remember: I am building real habits, not just collecting tool names.

HIDS lab

From script output to useful reporting

The HIDS project is my strongest signal because it connects Linux, Bash, baselines, checks, and alert output. The improvement path was learning that a security script is only useful when another person can understand what happened.

What changed: less noisy output, clearer wording, and stronger structure around repeatable checks.

Port scanner

Networking through code

The Python scanner helped me understand that ports, services, and timeouts require careful interpretation. A scan result can be useful, but it can also mislead if blocked traffic, host state, or timing is ignored.

What changed: more respect for validation, error handling, and explaining limits.

Packet Tracer

Troubleshooting one layer at a time

The networking labs trained the habit of checking assumptions before changing configurations. Addressing, interface state, routes, and test commands matter because random changes make problems harder to solve.

What changed: better labels, clearer diagrams, and slower, more deliberate verification.

Frameworks

Security needs business language

The NIST, CIS, and CIA triad notes show that tools are only one part of security. A finding should explain what is protected, what can fail, and which control reduces risk.

What changed: fewer vague security statements and more direct risk explanations.
